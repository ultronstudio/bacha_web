# Optional URL metadata and isolated inspector

- No network crawling is enabled by default. A caller must deliberately set `inspectLinks: true` after being told that the target (without query/fragment) can be visited from a scanner. Existing Android clients do not send this field yet.
- RDAP: set `BACHA_RDAP_ENABLED=1` after registry terms/privacy review. Fixed authoritative endpoints for .cz, .com and .net only (CZ.NIC and Verisign official documentation). Only registration age is consumed, never contact information. Unsupported, throttled or unavailable responses are UNKNOWN. New domains are weak evidence only.
- Redirect/static form inspection: set `BACHA_LINK_INSPECTOR_URL` to the dedicated TLS endpoint and `BACHA_LINK_INSPECTOR_TOKEN` to a new dedicated secret. No direct target fetch from the API. Deploy tools/link-inspector as a separate network-isolated service, without application/DB/cloud credentials or mounts, with outbound firewall explicitly blocking private, link-local, metadata, VPC and internal ranges, and only public DNS and HTTP(S). TLS/reverse proxy, request limits and secret storage are deployment responsibilities. Do not enable until these controls and privacy disclosure are tested. The Dockerfile is a packaging artifact, not evidence isolation was deployed.
- Worker: IPv4 only, public addresses, DNS pinning per hop, standard ports, no URL credentials/query/fragment, max four redirects, 6.5 seconds, 32 KiB of static HTML. No scripts, browser, subresources, forms or personal data. A blocked or failed check is not a clean verdict. Static form detection is heuristic; it cannot establish brand impersonation by itself.
- Google Web Risk lookup, PhishTank and URLhaus adapters are already present. Web Risk may incur fees; URLhaus community/commercial terms need verification. Do not activate providers without credentials and licensing review. No live secrets have been created.
